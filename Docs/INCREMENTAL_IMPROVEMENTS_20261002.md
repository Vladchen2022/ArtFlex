## 决策与范围

复用 `PersistenceController`、`LayerTextureSerializer`、`PersistenceSaveQueue`、现有恢复调度、文档代次和编辑版本检查。正式工程保存需要返回结果；素材库已有的无结果串行队列继续保留，避免为共用一个名字而改变两者语义。

正式保存任务交给独立 `ProjectSaveCoordinator`；文件面板和 UI 留在平台层。工具对持久化的阻挡规则集中为纯值策略，并建立不依赖 AppKit、SwiftUI 或 Metal 的小型编译模块。恢复写入与打开流程继续复用已有实现，不另建通用工作流引擎。

性能改进只针对正式保存的 GPU 冻结等待。先把复制命令提交到原画布队列，再在后台等待它完成并验证状态，之后才读回和写文件。CPU 可访问的源纹理保留同步保护；稀疏纹理相关资源必须保持到复制完成。不改变工程格式、压缩算法、颜色规范或笔刷算法，不提高内存预算。

原生方案依据：[Metal 命令提交](https://developer.apple.com/documentation/metal/mtlcommandbuffer/commit%28%29)、[命令队列排序](https://developer.apple.com/documentation/metal/mtlcommandbuffer/enqueue%28%29)、[完成处理与状态检查](https://developer.apple.com/documentation/metal/mtlcommandbuffer/addcompletedhandler%28_%3A%29)。本轮实际读取了这些官方页面的 Markdown 内容。

## 测量方法与预设门槛

- 本机 Apple M4 Max，128 GiB 内存，macOS 27.2（26B5091g）。
- 固定 2048 和 4096 正方形画布，4 张绘画纹理加 1 张 R8 蒙版；分别测 BGRA8 sRGB 与 RGBA16F。
- 每组首次样本单列，随后 5 次取中位数及范围；不报告样本不足的 p99。
- 使用同一优化测试配置 `swift test -c release -Xswiftc -DDEBUG`，保留现有测试所需 DEBUG 接口。最终安装另外执行不带该标志的正式 Release 构建。
- 改前与改后对照线程返回时间、复制完成时间、Metal 当前分配量和进程 RSS 历史峰值。RSS 与 GPU 字节不能相加，RSS 历史峰值也不是单次操作的新增占用。
- 进入优化的门槛：4096 场景的冻结调用中存在至少 1 ms 的可移出调用线程的等待。改后目标为入口阻塞中位数减少至少 25% 且至少 1 ms；完整复制中位数无稳定超过 20% 的退化，纹理分配不因改造增加一套副本。
- 这些门槛用于判断局部改动是否有实际价值，不代表笔尖到屏幕延迟或完整工程保存时间。

## 实际改动与职责归属

| 范围 | 改后行为及归属 |
| --- | --- |
| 正式保存 | `ProjectSaveCoordinator` 独占正式保存任务、忙碌状态、后台执行和一次性完成回调；拒绝重复开始，失败后可重试。已接受的写入即使调用者释放也会完成收尾。 |
| 文件 UI | 面板、状态文案、工程名和当前文档的最终更新保留在 `WorkspaceViewModel`；保存请求携带文档代次和编辑版本，旧版本保存完成不能清除后来编辑的脏状态。 |
| 工具边界 | `PersistenceEditingActivity` 汇总工具状态，`DocumentPersistencePolicy` 统一手动保存和自动恢复的判定。裁剪阻挡手动保存，但自动恢复仍可捕获已确认画布，因为裁剪边框只存在于 UI；未完成的纹理/套索手势会阻挡保存或延后恢复。调色和待确认直线仍走现有手动提交规则。 |
| 自动恢复 | 保留增量恢复、强制延期上限、代次检查与轮换；新增在打开工程、确认文档切换和文件面板期间延后捕获，避免多个入口各自漏判状态。 |
| GPU 冻结 | `enqueueProjectCapture` 在编辑边界取得元数据并提交复制；`DeferredTextureCloneBatch` 不提供未完成纹理的读取入口。后台确认复制成功后才转成 `FrozenProjectCapture`。 |
| 资源生命期 | 复制期间显式持有源纹理和稀疏 heap；后续私有纹理写入仍在原画布队列排序。shared/managed 等 CPU 可访问纹理保留同步复制完成保护。 |
| 编译边界 | 新增 `ArtFlexPolicies` target，仅包含纯值策略，不依赖平台或渲染模块。主程序依赖策略模块，方向单一；这不等于其余 Core 已经平台无关。 |
| 观测 | 复用 `PerformanceAuditStore`，补齐准备、GPU 等待、读回物化与写入阶段指标；新增有开关且规模固定的保存冻结对照测量。 |

正式保存采用提交后在 utility worker 等待的方式，没有引入通用异步桥接框架。该 worker 仍会等待 GPU；改善针对主线程阻塞，不是让 GPU 复制消失。

## 冻结性能结果

单位为毫秒，表内均为后续 5 次的中位数；斜线分隔改后两轮。8 位为 BGRA8 sRGB，16 位为 RGBA16F。同步对照与延后等待在同一个优化后的二进制中交替执行。

| 画布 / 精度 | 改前同步入口 | 改后同步对照入口 | 改后延后等待入口 | 改后延后路径完整复制 |
| --- | ---: | ---: | ---: | ---: |
| 2048 / 8 位 | 2.836 | 1.780 / 1.780 | 0.038 / 0.032 | 1.619 / 1.799 |
| 2048 / 16 位 | 3.352 | 3.197 / 3.192 | 0.042 / 0.034 | 2.996 / 3.163 |
| 4096 / 8 位 | 6.313 | 5.796 / 5.789 | 0.045 / 0.055 | 5.722 / 5.789 |
| 4096 / 16 位 | 13.219 | 13.211 / 13.248 | 0.068 / 0.064 | 13.477 / 13.228 |

两轮 4096 延后入口的全部后续样本范围为 0.044–0.093 ms。入口阻塞降低达到预设门槛；完整复制相对同轮同步对照没有稳定超过 20% 的退化。改前与改后完整复制的微小差异不能解释为 GPU 提速，尤其首次编译、缓存和频率会影响小样本。

相同场景、相同采样点的 Metal 分配量完全相同：2048 的 8 位/16 位分别约 137/265 MiB，4096 分别约 545/1057 MiB（含源与目标副本）。该实现没有增加第二套冻结副本，也没有减少整层副本所需的显存。`ru_maxrss` 记录约 53 MiB，但该计数不能代表 Metal 私有资源的总驻留量，不能用它声称整个保存过程只占用这些内存。

[原始样本与测量条件](Measurements/SAVE_CAPTURE_20261002.json) 保留所有首次与后续样本。这个实验只隔离纹理冻结阶段，不能推导完整保存快了多少、UI 所有帧都不再阻塞或长时间内存已稳定。

# 2026-10-02 续改记录（构建 20261002.29）

本节记录上一轮报告之后的改动。前文“尚未实施”的条目描述的是构建 .28，不能作为 .29 的现状。此次继续完成文档生命周期所有权、渐变工具操作边界、独立模块约束，以及有实测依据的局部资源试点。仍没有全面重写所有工具和渲染资源。

## 决策、复用与实施边界

1. 生命周期复用 `ProjectSaveCoordinator`、现有持久化捕获与恢复安装接口。Swift `Task` 的取消是协作式的，因此保留文档版本、任务代次和落盘前失效检查；不能只调用 `cancel()`。新 `ArtFlexLifecycle` target 只依赖 Foundation，持有文档身份和调度规则；AppKit 面板仍在平台层。没有引入通用工作流库。
2. 工具组选定线性渐变与扇形渐变。沿用现有几何、shader 和工具入口，新增会话对象持有草稿、提交令牌及后续动作。先渲染未发布结果，确认 GPU、源文档和历史捕获均成功后才替换像素。复现依据是历史捕获被拒绝时，旧路径仍改了像素、清掉草稿并切走工具。
3. 资源处理先测完整工作负载，再复用 `HistoryController` 的区域快照及反向区域捕获。带蒙版图层此前只提供内容快照，校验要求内容与蒙版齐全，因而退回整层捕获。本次补齐相同区域的蒙版；不放宽历史完整性检查。
4. 局部暂存复用 `SparseLayerTexture.copying`、`SparseTileScanner` 和原生 Metal 稀疏纹理。选区写入范围由现有光栅化范围和 scissor 决定，不按鼠标轨迹猜边界。只在支持的硬件、大画布、小区域且低占用时使用；高占用、全局操作与普通存储继续使用完整纹理。失败不发布暂存结果。
5. 进一步审计确认部分入口忽略历史捕获失败。对直线、套索填充、纹理实心填充、剪切、生成器提交、变形确认、图层属性和蒙版手势增加失败停止条件；保留其正常操作算法。

试点前的门槛是局部历史／暂存内存至少下降 75%，对应操作有超过噪声的改善，邻近操作没有稳定超过 20% 的退化，并通过 8/16 位像素、蒙版、撤销重做、共享方案及失败分支对照。内存收益不能通过丢弃历史、降低精度或放松校验获得。

官方依据：[Swift Task](https://developer.apple.com/documentation/swift/task)、[ContinuousClock](https://developer.apple.com/documentation/swift/continuousclock)、[应用退出回调](https://developer.apple.com/documentation/appkit/nsapplicationdelegate/applicationshouldterminate(_:))、[稀疏纹理内存映射](https://developer.apple.com/documentation/metal/assigning-memory-to-sparse-textures)、[稀疏纹理读写](https://developer.apple.com/documentation/metal/reading-and-writing-to-sparse-textures)。稀疏目标先映射并初始化，未映射读为零；不能依赖命令成功状态自动证明堆容量足够，因此继续按原生 tile 数量分配容量。

| 对象 | 拥有的状态与边界 |

| `StageOneLayerSurfaceStore.StagedPixelEdit` | 编辑源身份、未发布结果及稀疏堆生命期；发布时检查源仍一致 |

`WorkspaceViewModel` 不再重复持有上述生命周期和渐变状态，但仍负责平台事件、几何输入适配和装载完成后的工作区安装。它仍然很大，其他工具、参考图、资源库等职责尚未全部拆分。`ArtFlexLifecycle` 与已有 `ArtFlexPolicies` 有编译约束；不能据此声称整个 Core 已跨平台。修饰键的 AppKit 转换已移到平台层。

渐变切层会先提交到原图层，成功后再切层；提交失败保留原图层和草稿。提交中的 Esc 或撤销取消尚未确认的结果，晚到 GPU 回调不再发布像素。普通图片导出、工程格式、颜色规范和既有主界面结构未改变。

## 工作负载与性能证据

工作负载为 2048／4096 方形画布、BGRA8 sRGB／RGBA16F、4 个绘画图层、当前层有蒙版。每组 6 个样本，保留首次样本，表格使用后 5 次中位数。每次包含固定种子的 24 点笔触、提交、撤销重做、64×64 选区填充、完整保存并校验重开。笔刷大小和随机参数显式固定；每轮开始解除上轮测试选区约束。

较早试运行遗漏了每轮选区重置，已作废其绘画性能结论并重新测量。正式前后样本使用同一修正后的测试输入。编译采用 Release 优化并开启 DEBUG 测试钩子；最终交付另做无 DEBUG 的 Release 构建。CPU 内存峰值和 Metal 分配量口径不同，不能相加作为物理内存。

单位为 ms；改后两列斜线分隔两轮独立运行。设备为 M4 Max、128 GiB 内存，不能代替低内存机器验证。

| 画布／精度 | 笔触提交 改前 → 改后两轮 | 选区完整操作 改前 → 改后两轮 | 改后强制普通暂存 | 暂存内存 改前 → 改后 |
| --- | ---: | ---: | ---: | ---: |
| 2048／8 位 | 6.24 → 1.94 / 2.09 | 5.60 → 1.41 / 1.36 | 1.72 | 16 MiB → 80 KiB |
| 2048／16 位 | 8.11 → 2.41 / 2.65 | 7.53 → 1.54 / 1.57 | 2.21 | 32 MiB → 128 KiB |
| 4096／8 位 | 22.02 → 3.05 / 2.83 | 22.64 → 2.13 / 1.89 | 3.34 | 64 MiB → 80 KiB |
| 4096／16 位 | 27.52 → 5.02 / 4.36 | 28.12 → 2.52 / 2.62 | 5.68 | 128 MiB → 128 KiB |

4096／16 位的撤销中位数从 49.71 ms 降至 4.75 / 4.58 ms，重做从 48.90 ms 降至 4.43 / 4.28 ms。相同采样点的历史常驻字节中位数从 720 MiB 降至约 317 KiB；这是该局部工作负载的历史驻留量，不是整个软件的内存。

4096／16 位完整保存为改前 1890.00 ms、改后 1887.83 / 1885.57 ms，基本不变。绘画阶段中位数为 8.64 ms → 9.37 / 8.86 ms，没有稳定超过 20% 的回退；不把该波动解释为笔触提速。保存后 Metal 分配量基本不变，仅多出对应的少量驻留 tile。

普通暂存对照使用相同优化二进制、相同局部历史，仅通过 DEBUG 开关强制完整纹理。其 4096／16 位选区操作为 5.68 ms，稀疏路径为 2.52 / 2.62 ms。两条路径的默认选择已收敛到容量与硬件条件，测试开关不进入 Release 用户界面。

原始数据、采样条件与来源版本见 `Docs/Measurements/INTERACTIVE_WORKLOAD_20261002.json`。完整保存包含 CPU 读回、编码和文件写入，没有用冻结微基准代替完整保存。此次不能声称全部绘画临时纹理已区域化；画笔活动阶段和历史恢复仍有整层工作资源。
