# 撤销／重做对称局部快照（2026-09-08）

## 决策与实现计划

磁盘撤销界面验收发现：小笔触初次入栈占用很小，但经过多步撤销／重做后，像素历史内存明显上升。代码确认，目标历史虽含局部区域，逆向记录仍通过 `makeEntry` 抓取整张受影响图层。

复用 `LayerHistorySnapshot` 的 origin／尺寸、`validatedProvidedLayerSnapshots` 和 `LayerTextureSerializer.snapshotRegions`，不增加一种撤销格式，不自建传输系统。Metal 区域读取已存在；大区域沿用现有分块 `snapshot` 回退。这比新增脏区域追踪框架小得多，也不需要修改笔刷算法。

执行顺序：先用字节数与整图像素测试复现，再令逆向快照使用同一区域，补内容／蒙版／磁盘预算／大区域测试，最后安装界面验收。

## 可验证结果

- 256×256 图层中一个 12×13 的变更区域，初始历史为 624 字节。修改前，第一次撤销后扩大为 262,144 字节；四轮撤销／重做共触发 8 次大小断言失败，像素断言不失败。
- 修改后，每次仍为 624 字节，区域外哨兵像素和整张图层的前后状态逐字节一致。
- 内容区域 8×9、蒙版区域 7×11 且位置不同，三轮来回保持 365 字节，完整内容和蒙版逐字节一致。
- 128×128 画布上 20 个 5×5 区域，像素内存预算 400 字节、磁盘预算 2,000 字节；20 步来回均保留，每个状态的整图像素一致，常驻历史像素最多 200 字节。
- 4097×4097 区域超过 64 MiB，走现有分块读取；原点 (1,1) 的偏移及末端哨兵像素正确，暂存池不超过 16 MiB 的测试预算。
- 定向 47 项通过，0.763 秒；此前含整个像素历史套件的 121 项通过，3.192 秒。
- 两轮全量均为 935 项／85 套通过，分别 38.645 秒、38.297 秒。

这些数字仅是对应测试的历史像素占用，不能说整个应用内存降低了相同倍数。

## 代码与文件

- `Core/Application/HistoryController.swift`：仅稳定图层结构下的局部历史抓取同范围逆向快照。仍保留现有数据完整性检查；其他历史类型不变；先读好当前像素再恢复目标，失败不弹出记录。
- `Infrastructure/FileFormat/LayerTextureSerializer.swift`：区域批量读取中有超大区域时，复用已有分块读取，避免一次分配整块 CPU 暂存纹理。
- `Tests/ArtFlexTests/HistoryControllerTests.swift`：局部内存、区域外像素、不同内容／蒙版边界和小预算磁盘链测试。
- `Tests/ArtFlexTests/LayerTextureSerializerQueueSafetyTests.swift`：大区域分块与偏移测试，使用独立性能记录器。
- 构建号 `20260908.21`、本记录和状态索引。

- Computer Use 在测试工程中隐藏旧灰色试笔层、新建图层，画出两列共 12 笔红色试笔。历史为 14/14（另两步是图层操作），像素历史内存 1.8 MB、磁盘 4 KB（4 步）。

- 拉回 14/14，12 笔完整返回，历史再次显示内存 1.8 MB、磁盘 4 KB（4 步）。没有出现此前整层逆向快照造成的几十 MB 膨胀。

手测：连续画若干小笔触，记录历史窗口的内存值；来回拖动历史并恢复起点，像素应一致，历史占用不应仅因来回撤销就永久扩大成全画布大小。复杂整层操作本来需要更多内存，不适用小区域的字节数预期。

测试开发过程中修正过嵌套 `#require` 宏和误调用私有清屏方法的编译错误；它们不是产品运行故障。复现产品范围膨胀的日志为 `/tmp/artflex-region-history-before-2.log`，修复后为 `/tmp/artflex-region-history-targeted-final-2.log`。

## 风险与后续

恢复时仍通过完整 GPU 临时图层验证后交换，以保留失败原子性；本批只减少历史记录与读回的数据范围，未取消那份 GPU 暂存。整层调整、图层结构变化等操作保留原有快照路径。稀疏图层存储和增量自动恢复尚未实施，不能把本改动称为已完成这些架构任务。
