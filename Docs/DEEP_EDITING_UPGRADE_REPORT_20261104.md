## 改造内容与实际区别

| 项目 | 改造前 | 改造后与交付边界 |
| --- | --- | --- |
| 1. 绘画性能诊断 | 缺少可在界面检查的完整分位数记录 | “显示 → 绘画性能诊断”记录应用输入队列至系统呈现、CPU/GPU 编码执行及 P95/P99，可导出原始 JSON；固定工作负载有回归门槛。数值不包含数位板驱动和屏幕响应。 |
| 2. 局部图层合成 | 复杂图层连续绘画容易重复全画布合成 | 有明确变更区域时仅重算区域，混合、蒙版、剪贴、曲线逐像素对照；预览或资源版本变化等情况仍走完整合成。 |
| 3. 共享资源预算 | 文档估算、实际 GPU 占用和临时资源缺少统一约束 | 共享实际驻留占用和临时分配预留，结合稀疏图层及可重建缓存回收；多文档共用同一 Metal 服务和预算。没有宣称所有工作负载都大幅省内存。 |
| 4. 渐进打开与安全取消 | 文件处理过程不够可见，取消边界不足 | 打开按资产读取、验证和准备 GPU 表面；保存显示阶段并在正式替换前响应取消；失败/取消打开返回原文档，不留下临时空白标签。单个系统编码/解压调用需要等待安全边界。 |
| 5. 无损图像图层 | 多次变形会在已变形结果上累积重采样 | 转为可编辑图像后保留原始源，位置、比例、旋转每次从源重算；支持取消、撤销、重做、重开后修改和恢复源图。直接绘画前需新建层或显式栅格化。 |
| 6. 可编辑填充图层 | 纹理、渐变确认后主要剩下像素 | 可选择保留底稿、区域、冻结素材、随机种子、颜色和参数，之后继续编辑；普通直接填充保留。纹理、直线渐变和扇形渐变共用正式图层结果。 |
| 7. 持久方案分支 | 试探方案难以作为完整结构长期保存 | 最多 8 个命名方案随工程保存，可继续编辑或选择图层合入；组、蒙版、混合和可编辑源保留，合入是单次可撤销事务。 |
| 8. 多文档与同稿双视图 | 主要围绕单一活动工作区 | 独立文档标签、历史、文件与恢复目录；支持图层跨文档复制，另有独立缩放的同稿只读观察视图。跨不同精度/工作色域复制目前明确拒绝。 |
| 9. ICC、P3 与 RGB 校样 | 颜色链路以原有 sRGB 为主 | 新建 16F 可启用广色域；ICC 导入、扩展像素取样、P3/自定义 RGB ICC 导出以及仅影响显示的 RGB 校样贯通。旧工程保持原颜色路径，不包括 HDR 提亮或 CMYK 纸墨模拟。 |
| 10. 分层交换 | 主要依赖原生工程和合并图片 | 新增 ORA 像素层、名称、正偏移、透明度、可见性、穿透组及八种混合模式交换；不支持的结构明确拒绝，可主动选择合并图像。PSD 仅完成可行性评估，未声称支持 PSD 分层读写。 |

## 复用与架构决定

继续使用正式 Metal 图层作为显示、取样和导出的共同数据源。无损源和参数负责重建图层，不引入另一套 CPU 画布。复用现有历史事务、冻结资源、工作区、归档校验、平台文件面板和原子替换。

ICC 使用 Core Graphics/ColorSync，校样使用 Metal Performance Shaders。ORA 的 ZIP 容器使用固定版本 ZIPFoundation 0.9.20，MIT 许可随安装包分发；包验证和构建指纹覆盖新增资源。具体原生 API、规范链接与逐项决策见 `DEEP_EDITING_UPGRADE_20261104.md`。

工程读取版本随能力升级：可编辑源需要读取版本 4，广色域需要版本 5。旧工程可继续打开；使用新能力保存的工程不能保证由旧安装包读取。回退应用时应使用此前保存的工程副本。

## 自动测试与性能证据

最终完整测试：1093 项、121 个测试套件通过，耗时 54.730 秒。日志：`.build/deep-upgrade-evidence/full-release36-tests.log`。另有颜色、资源预算、区域合成、文件安全、分支与图层事务的针对性测试记录。运行这些测试补充像素、字节、事务和失败路径证据；可见验收另列如下。

性能对照为同机 Release 优化、相同测试钩子、同一工况，每种 31 次，其中首个热身剔除，30 个有效样本。旧版源来自基线 Git 归档；两边测试方法一致；计时期间不同时编译或操作画布。绘画项目计量一组固定输入及 GPU 完成，不是硬件到屏幕的端到端延迟。

| 工况 | 绘画 P95 旧 → 新（ms） | 保存 P95 旧 → 新（ms） |
| --- | ---: | ---: |
| 2048²、8 位 | 3.056 → 2.501 | 179.668 → 178.728 |
| 2048²、16F | 3.168 → 3.202 | 288.918 → 290.271 |
| 4096²、8 位 | 3.201 → 3.040 | 565.392 → 557.618 |
| 4096²、16F | 4.354 → 3.585 | 994.417 → 993.988 |

绘画、提交、撤销、重做、保存及保存主线程准备的 P95 均通过既定 20% 退化门槛。最大增幅约 14.1%，不能写成每个环节都变快。P99 同时输出，但 30 样本的 P99 接近最大值，仍不足以说明长期尾部表现。

独立 GPU 合成对照（12 层、64×64 变更区域、20 个有效样本）中，2K 的 P95 为 1.300 → 0.484 ms，4K 为 2.836 → 0.476 ms。它只证明这一合成场景的收益，不能推导整套绘画速度同等提升。

初轮各 5 个有效样本时出现 5～6 项门槛失败，因此保留失败记录并扩大样本重测，没有降低门槛。最终日志为 `baseline-31-workload.log`、`final-31-workload.log`、`workload-31-comparison.jsonl`。同期完整进程峰值 RSS 约 819.3 → 815.3 MB，整体基本持平；4K 8 位阶段约 772.5 → 686.5 MB。早期小样本曾出现更大的内存差异，复测未稳定重现，因此不作为交付收益。

## 可见界面验收

验收稿保存在桌面 `ArtFlex 深度升级验收` 文件夹，用户可直接打开复查。

- **无损图像**：画出交叉笔画，缩放至 0.5/0.5、旋转 30°；先取消，再应用，撤销/重做；保存并重开后参数仍在，恢复源图预览正确。文件 `01-无损图像.artflex`。
- **可编辑渐变**：新层绘制黑色至透明渐变，保留参数，反转渐变、应用、撤销与重做；另存 `02-可编辑渐变.artflex`。
- **可编辑纹理**：使用由既有 Metal 测试生成的 24×16 确定性样本打开参数窗口，将覆盖从 70% 改到 8%；预览可见改变，取消与撤销恢复 70%，重做后保存并重开仍为 8%。文件 `07-可编辑纹理.artflex`。这验证参数重编和持久化，不代替原始曲线手势输入测试。
- **持久方案**：保存“保留构图A”，继续编辑另一方案，仅选一个图层合入主稿形成组；撤销/重做整个组；重开后命名方案仍存在。
- **文档隔离**：多份文档同时打开；复制参数图层到 ORA 导入稿，目标出现独立组和可编辑参数，源稿仍显示已保存；目标撤销只移除复制内容。关闭未保存稿时点取消，文档保留。
- **同稿观察**：主画布新增笔画同步到观察视图，观察缩放独立。验收发现深色工具条文字对比度不足和倍率含义不清，已改为深色环境及“适合 × 倍率”。
- **ORA**：从原生稿导出分层 ORA，再导入新标签；组、层次和画面保留，原生参数稿独立。导入结果保存为 `03-ORA重新导入.artflex`。
- **P3**：界面新建 512²/16F/广色域，粘贴带 P3 ICC 的色卡，启用 sRGB 校样；吸管仍读到原稿扩展通道（约 1.093、−0.227、−0.150），关闭校样恢复观察；界面导出 PNG，文件核对为 512²、16 位、内嵌 Display P3。文件 `04-P3广色域.artflex` 和同名 PNG。
- **文件作业**：导入 4096²/12 层普通及噪声压力工程；实际在保存资源读取阶段点击取消，画稿保留，首次取消不留下最终文件；再完整保存并修改，取消覆盖保存后 SHA-256 与原文件一致。原生打开在“读取并准备图层 4 / 12”取消，未发布部分图层。
- **诊断窗口**：界面开始记录、实际绘画、停止记录和导出 JSON 均完成，输入、CPU、GPU 等栏出现样本。`ArtFlex-performance.json` 是功能验收记录，样本少，不用它宣称性能提升。

可见验收发现并修正了四处问题：双视图文字/倍率、文档切换后的最近工程列表、ORA 兼容说明截断、取消打开留下临时标签。四项均已在正式安装版本上复验，详见下方。

## 已知边界与尚未验证部分

- ORA 在 ArtFlex 内的结构往返、危险输入和颜色测试通过。Krita/GIMP 在当前机器无法取得可操作窗口；Finder 打开 Krita 也返回 AppleEvent 超时。因此**没有把真实跨应用往返记为通过**，发布范围仍是明确子集。
- ORA 不保留原生可编辑参数、方案、体块、历史和画布外像素；隔离组、蒙版、剪贴和调整层暂不支持结构交换。PSD 留待独立解析库审计和真实样本对照。
- 可编辑纹理的原始曲线手势受当前界面工具只能直线拖动的限制；参数稳定性及种子由自动测试覆盖，界面参数复验使用确定性工程样本，不伪称完成曲线手绘输入验收。
- RGB 校样不是印刷软打样；颜色数值链路通过验证，不代表用户显示器已经校准。原有艺术颜色活化工具也不承诺保留全部广色域极值。
- 本轮没有在 Windows 构建或运行。平台 UI、系统面板与 Metal 实现继续分层，但这不等于已经具有 Windows 后端。
