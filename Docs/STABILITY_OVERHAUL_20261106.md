## 改造结果对照

| 项 | 修正前的隐患 | 修正后的行为 |
| --- | --- | --- |
| 1 恢复 | 恢复来源与当前会话目录混用，旧代/方案副本可能遗漏 | 来源只读；新会话独立拥有恢复目录；失败、取消、关闭不删除来源 |
| 2 素材库 | 文档各持一份库状态，交错保存可能覆盖别人的修改 | 应用共享库和唯一写队列；文档保留自己的选择；退出等待写完并报告失败 |
| 3 文件 | 另存为可撞到另一文档；磁盘外部修改可能被覆盖 | 文件身份与待写占用统一登记；原生文件协调；外部版本改变即停止覆盖 |
| 4 图层事务 | 分配或 GPU 操作失败时可能已经修改图层列表、历史和脏状态 | 先准备资源与文档候选，再一次性发布；失败保留原稿与撤销栈 |
| 9 色域 | 同一张图按单个像素是否越界选择调色算法，边界可能跳变 | 整个文档固定工作域；8 位旧行为和 16F/P3 连续性有像素对照 |
| 5 内存 | 主要关注单文档/GPU，忽略其他文档和后台 CPU 数据 | 共享 CPU/GPU 预算；任务持有预留直到消费结束；回收覆盖非活动文档 |
| 6 快照与历史 | 保存冻结容易整层复制；完整历史恢复可能把稀疏层变密集层 | 异步保存持有不可变 COW 引用；约 2 MiB 分段读回/压缩；透明历史恢复重新按占用区域映射 |
| 7 主线程 | 裁剪保留像素、源素材捕获和压缩卡住输入 | 独立后台准备、取消检查、文档版本核对；主线程提交；预览按所属编辑器串行 |

## 验证范围与边界

- 全量自动测试日志：`.build/stability-evidence/full-tests.log`。专项日志位于同一目录。测试覆盖分配/GPU/历史/磁盘失败、跨文档交错操作、取消与过期结果、颜色与像素往返。
- 稀疏快照测试在 4096 × 4096 图层上验证冻结共享资源、随后写入分离、占用小于同尺寸密集图的十分之一；这不是对所有画稿的性能倍率承诺。
- 约 2 MiB 指读回条带的大小。压缩后的层数据和工程验证仍有内存成本，预算也保留保守余量。
- 旧同步冻结 API 保留整层独立复制。密集图层在冻结后的首次写入仍可能复制整层；稀疏能力取决于设备支持，没有声称 Metal 可以共享同一物理页的可写映射。
- 大源资产缓存上限 4 GiB，64 KiB 以上压缩资产落盘；容量不足拒绝新操作，不驱逐仍被画稿或历史引用的素材。工程文件仍自包含，不依赖临时缓存才能跨设备打开。
- 文件变化识别结合原生协调和文件身份/大小/修改时间；不声称能识别刻意保留全部元数据的外部篡改。
- 本次集中的是编辑状态、任务生命周期与提交边界；WorkspaceViewModel 仍承担大量界面适配，不宣称整个程序已完成跨平台拆分。
- 不在真实画稿上强制模拟磁盘满或 GPU 故障。这些失败路径通过临时目录和自动化注入验证；正常操作另做可见界面验收。

## 可见验收发现与追加修复

20261106.40 的真实窗口验收发现：新建第二文档并绘画后，历史预览有 4 步、命令搜索的撤销可用，但原生编辑菜单的撤销禁用。说明自动化模型测试没有覆盖 SwiftUI Scene → Commands 的观察链。

修复决策：复用当前文档控制器与统一命令解析，改用 Apple `focusedSceneObject` / `FocusedObject` 让 Commands 直接观察当前场景，替换从 App 层间接传递活动模型的方式。来源：https://developer.apple.com/documentation/swiftui/focusedobject 与 https://developer.apple.com/documentation/swiftui/view/focusedsceneobject(_:)。不以后台测试替代再次打开原生菜单验收。验收画稿已保存为桌面的 `ArtFlex-Stability-Acceptance-20261106.artflex`。

追加修正版为 `20261106.41`；以下最终安装记录以修正版为准。

20261106.41 再次可见验收仍失败，故没有作为完成版本交付。进一步检查发现系统替换菜单组处于多层条件 Commands 内；“图层”等追加菜单可见，但文件菜单和撤销替换未生效。这一证据推翻了“只修观察链即可”的判断。

参考报告：Apple [Building and customizing the menu bar with SwiftUI](https://developer.apple.com/documentation/swiftui/building-and-customizing-the-menu-bar-with-swiftui) 将系统菜单替换放在固定 CommandGroup 结构中，焦点只决定菜单内容/可用性。20261106.42 据此把所有替换组固定注册，条件转移到组内 View；保留当前文档、方案与编辑器的独立观察和统一命令执行入口。未增加自制 NSMenu 基础设施。必须以最终界面中的文件菜单、撤销/重做和文档切换验收确认。

回归中另发现两个测试等待条件问题：源素材准备测试在全量 GPU 并发压力下将排队误判为失败，改为等待实际任务完成并保留 60 秒上限；曲线预览测试使用共用重绘计数却只检查色彩调整的在途标记，补齐曲线任务完成条件后才比较像素。像素断言保持不变，没有跳过测试。
