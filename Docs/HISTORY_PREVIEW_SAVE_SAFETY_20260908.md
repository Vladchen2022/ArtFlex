# 历史预览的保存与恢复保护（2026-09-08）

## 决策与实现计划

局部撤销的界面测试期间出现自动恢复提示，进一步检查发现：历史预览通过真实撤销／重做临时替换工作区内容；取消才回到原状态，应用才接受新状态。此前自动恢复和手动保存入口未排除这段临时状态。

这不等于原工程会被自动删除，但可能让未确认的旧状态成为最新恢复副本，也允许手动保存临时状态。先用确定性测试复现，再保护持久化入口，最后通过界面检查取消／应用／保存。

仓库复用：沿用现有 `visibleHistoryPreviewOriginCount` 状态、`canBeginDocumentPersistence` 保存入口保护，以及退出预览后 `hasUnsavedChanges` 的自动恢复调度。已有异步冻结快照和后台写入继续使用。平台文件面板和 Foundation 文件写入不负责区分业务上的临时预览；无需另建存储格式或引入依赖。

## 代码与文件

- `Platform/macOS/App/WorkspaceViewModel.swift`：预览期间不捕获新的恢复快照；手动保存、新建、打开、导出和退出的共用入口要求先取消预览或应用此状态。预览前已冻结的保存任务仍可正常完成。退出预览后重新调度恢复，不在停留预览时轮询。
- `Tests/ArtFlexTests/FileWorkflowSafetyTests.swift`：新增 4 项测试，检查恢复文件字节不变、预览前冻结任务正确落盘、手动保存的拒绝与恢复、应用旧状态后可以生成新恢复点；额外断言调度确实暂停及恢复。
- `Platform/macOS/Distribution/Info.plist`：构建 `20260908.22`。
- 本记录及 `CURRENT_STATUS.md` 状态入口。

## 手测清单

1. 在独立测试工程做两次可撤销操作，打开历史预览，返回更早状态；Cmd+S 应提示先取消或应用，不直接保存。
2. 点击取消，两个操作应返回；正常保存并重开，应保留取消后画面。
3. 再次预览更早状态，点击应用，保存并重开，应保留明确接受的旧状态。
4. 有未保存修改时停留预览超过 30 秒，现有恢复副本不能被临时状态覆盖；取消或应用后自动恢复应继续工作。本项可结合文件时间／校验检查，不能只看恢复菜单是否存在。

## 风险与边界

- 这是已复现的临时预览持久化缺陷，不能据此认定过去每次工程丢失都由它造成。
- 历史预览暂时冻结新的恢复捕获，长时间停留后异常退出只能使用预览前的恢复点；不会把未确认的旧画面冒充最新画稿。
- 自动恢复仍包含整套图层资源，增量恢复与稀疏图层存储尚未完成。
- Shift+Z 持续按住快捷调色窗的硬件手测仍未收到确认，不能算已完成该交互的验收。
